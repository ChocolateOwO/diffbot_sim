## 1. ภาพรวมก่อน

*(หน้าจอ: โชว์ `plan.png` ค้างไว้)*

โปรแกรมแบ่งเป็นสองส่วนหลัก ส่วนแรกคือตัววางแผน ทำงานแบบ offline คือคิดเส้นทางให้เสร็จก่อน ยังไม่ได้ขยับหุ่นเลย ส่วนที่สองคือตัวขับ เอาเส้นทางที่ได้ไปสั่งให้หุ่นยนต์ใน Gazebo วิ่งตาม

สองส่วนนี้คุยกันผ่านไฟล์ `plan.json` ไฟล์เดียว ในนั้นมีตำแหน่งเริ่มต้น ตำแหน่งเป้าหมาย และรายการโหนดของเส้นทางเรียงตามลำดับที่หุ่นต้องผ่าน

ในรูปนี้ ฝั่งซ้ายคือแผนที่ OGM สีเทาและสีดำ จุดเขียวคือตำแหน่งเริ่มต้น จุดแดงคือเป้าหมาย ลูกศรบอกทิศที่หุ่นหัน เส้นฟ้าหนาคือเส้นทางที่ RRT* หาได้ เส้นฟ้าอมเขียวบางๆ ทั่วแผนที่คือต้นไม้ของ RRT* ส่วนสีส้มคือบริเวณที่ตัวหุ่นเข้าไปไม่ได้ ฝั่งขวาคือภาพมองจากด้านบนของฉากจริงใน Gazebo วางเส้นทางเดียวกันทับลงไป

## 2. โปรแกรมวางแผน — rrt_star_planner_660610829.py

*(หน้าจอ: สลับไปที่ไฟล์ planner เลื่อนไปบนสุด)*

### 2.1 สิ่งที่โปรแกรมทำตามลำดับ

ตามที่โจทย์สั่งเลยครับ สี่อย่าง โหลดแผนที่ OGM สุ่มตำแหน่งเริ่มต้นกับเป้าหมายโดยไม่ให้ทับที่ที่หุ่นไปไม่ได้ หาเส้นทางด้วย RRT* แล้วเซฟผลออกมา

### 2.2 คลาส GridMap — ตัวเก็บแผนที่

*(เลื่อนไปที่ class GridMap)*

คลาสนี้ถือตาราง OGM ไว้ ค่าแต่ละช่องคือความน่าจะเป็นว่ามีสิ่งกีดขวาง ศูนย์คือว่าง หนึ่งคือตัน ศูนย์จุดห้าคือยังไม่เคยสำรวจ แถวบนสุดของตารางคือขอบบนของแผนที่ ช่องละสิบเซนติเมตร

ฟังก์ชัน `to_cell` กับ `cell_center` แปลงไปมาระหว่างพิกัดจริงหน่วยเมตร กับเลขแถวเลขคอลัมน์ในตาราง ต้องระวังเรื่องแกน y ที่กลับหัว เพราะแถวแรกของตารางคือ y มากสุด

**ฟังก์ชัน block_from_ogm** ตัดสินว่าช่องไหนหุ่นไปได้ ผมใช้กฎว่าช่องที่ไปได้ต้องเป็นช่องที่เลเซอร์เคยเห็นว่าว่างจริงๆ คือความน่าจะเป็นต่ำกว่าศูนย์จุดสี่สิบห้า ช่องที่ตันก็ไปไม่ได้ และช่องที่ไม่เคยสำรวจเลย ซึ่งคือศูนย์จุดห้า ก็ถือว่าไปไม่ได้เหมือนกัน เพราะเราไม่รู้ว่าข้างในมีอะไร อันนี้คือเลือกเอาปลอดภัยไว้ก่อน

**ฟังก์ชัน block_footprints** เอารูปร่างสิ่งกีดขวางที่ให้มา มาระบายลงในตารางว่าตัน อันนี้จะอธิบายอีกทีในหัวข้อของที่เลเซอร์มองไม่เห็น

**ฟังก์ชัน inflate** สำคัญมาก หุ่นของเราตัวใหญ่ หนึ่งเมตรคูณหนึ่งเมตร แต่ตัววางแผนเดินแบบจุดเดียว เลยต้องขยายสิ่งกีดขวางทุกอันออกไปเท่ารัศมีของหุ่น ผมตั้งไว้ศูนย์จุดแปดสิบห้าเมตร ซึ่งคลุมครึ่งเส้นทแยงมุมของตัวหุ่นรวมล้อ พอขยายแล้ว ถ้าจุดศูนย์กลางหุ่นอยู่ในช่องที่เหลือว่าง ตัวหุ่นทั้งตัวไม่ชนอะไรแน่ๆ ไม่ว่าจะหันไปทางไหน ข้อดีคือเราไม่ต้องเอามุม theta มาคิดตอนตรวจชนเลย ขอบของแผนที่ถือว่าเป็นสิ่งกีดขวางด้วย

*(โชว์ plan.png ฝั่งซ้าย ชี้สีส้มที่ล้อมรอบกำแพงและโต๊ะ)* ตรงนี้ที่สีส้มคือพื้นที่ที่ถูกขยาย จะเห็นว่าประตูที่กว้างสองจุดแปดเมตร หลังขยายแล้วเหลือช่องว่างให้ผ่านประมาณหนึ่งจุดหนึ่งเมตร

**ฟังก์ชัน points_free** รับรายการจุด แล้วตอบว่าแต่ละจุดอยู่บนช่องว่างหลังขยายหรือเปล่า ใช้ตอนตรวจว่าเส้นเชื่อมระหว่างโหนดชนไหม

**ฟังก์ชัน largest_free_region** หาว่าพื้นที่ว่างผืนไหนใหญ่ที่สุดที่เดินถึงกันได้ ใช้วิธีไล่แบบ BFS ทีละช่องรอบตัว เหตุผลคือถ้าสุ่มจุดเริ่มกับเป้าหมายไปตกอยู่คนละพื้นที่ที่ไม่ต่อกัน เช่น มุมอับที่ถูกล้อมไว้ RRT* จะหาเส้นทางไม่เจอเลย เลยสุ่มเฉพาะในผืนที่ใหญ่สุด

### 2.3 ของที่เลเซอร์มองไม่เห็น — คลาส Obj และ load_world

*(เลื่อนไปที่ class Obj และ load_world)*

มีเรื่องหนึ่งที่เจอตอนทำ คือเลเซอร์ LiDAR ของเราสูงจากพื้นศูนย์จุดหกแปดห้าเมตร มันเลยมองไม่เห็นของเตี้ยๆ เช่น โซฟา กรวยจราจร เบาะเก้าอี้ และตัวถังรถของเล่น ของพวกนี้เลยไม่อยู่ในแผนที่ OGM แต่ตัวหุ่นสูงตั้งแต่เกือบพื้น ชนมันได้จริง

เลยให้ตัววางแผนอ่านไฟล์ `.world` ของฉาก ดึงเฉพาะของที่ชนตัวหุ่นได้แต่เลเซอร์มองไม่เห็นมาเติมเป็นสิ่งกีดขวางเพิ่ม ตอนรันจะพิมพ์ออกมาว่าเติมไปกี่ชิ้น ได้หนึ่งร้อยสิบเอ็ดชิ้น

คลาส Obj เก็บรูปทรงของแต่ละชิ้น ว่าเป็นกล่อง ทรงกระบอก หรือทรงกลม ตำแหน่ง ขนาด และช่วงความสูง ฟังก์ชัน `seen_by_lidar` เช็คว่าระนาบเลเซอร์ผ่านชิ้นนี้ไหม ฟังก์ชัน `blocks_robot_body` เช็คว่าชิ้นนี้อยู่ในช่วงความสูงของตัวหุ่นไหม ของที่ตรงเงื่อนไขชนตัวหุ่นแต่เลเซอร์ไม่เห็น จะถูกเติมเข้าไป

มีตัวเลือก `--ogm-only` ให้ปิดส่วนนี้ ผมลองสุ่มสิบแผน ถ้าวางแผนจากแผนที่ OGM ล้วนๆ มีหกแผนที่เส้นทางผ่านใกล้ของที่เลเซอร์มองไม่เห็นจนชนได้ ใกล้สุดแค่ศูนย์จุดสองเจ็ดเมตร แต่พอเติมของพวกนี้เข้าไปแล้ว เป็นศูนย์แผน

### 2.4 สุ่มตำแหน่งเริ่มต้นและเป้าหมาย

*(เลื่อนไปที่ฟังก์ชัน random_pose และส่วน 3 ใน main)*

ฟังก์ชัน `random_pose` สุ่มเลือกช่องหนึ่งจากพื้นที่ว่างผืนใหญ่ที่หาไว้แล้ว แล้วสุ่มตำแหน่งในช่องนั้น กับสุ่มมุม theta ระหว่างลบพายถึงบวกพาย เพราะสุ่มจากช่องว่างหลังขยายสิ่งกีดขวางแล้ว ตำแหน่งที่ได้จึงไม่ทับที่ที่หุ่นเข้าไม่ได้แน่นอน

เป้าหมายสุ่มซ้ำจนกว่าจะอยู่ห่างจากจุดเริ่มอย่างน้อยสิบเมตร กันไม่ให้ได้เส้นทางที่สั้นเกินไปจนไม่น่าสนใจ ถ้าอยากกำหนดจุดเองใช้ `--start` กับ `--goal` ได้ และถ้ากำหนดมาแล้วไปทับที่ที่เข้าไม่ได้ โปรแกรมจะแจ้งเตือนแล้วหยุด ไม่วางแผนให้มั่วๆ

ค่า seed ที่ใช้สุ่มถูกพิมพ์ออกมาและเก็บใน `plan.json` ถ้าอยากได้จุดเดิมซ้ำ ก็ใส่ `--seed` เดิม

### 2.5 คลาส Node และ RRTStar — หัวใจของการวางแผน

*(เลื่อนไปที่ class Node และ class RRTStar)*

โครงสร้างตรงนี้ผมเอามาจากโค้ด RRT กับ RRT* ที่ทำในงานก่อนหน้านี้ ชื่อฟังก์ชันและตัวแปรตามสไลด์เหมือนเดิม สิ่งที่เปลี่ยนมีสามอย่าง การตรวจชนเปลี่ยนจากสี่เหลี่ยมเป็นการดูค่าในกริด การค้นหาโหนดข้างเคียงใช้ numpy ทำทีเดียวทั้งก้อน เพราะแผนที่นี้ใหญ่กว่าเดิมมาก ต้องใช้โหนดเป็นพันๆ ถ้าวนทีละโหนดจะช้า และการสุ่มจุดสุ่มจากช่องว่างโดยตรง ไม่ไปสุ่มโดนผนังแล้วเสียรอบฟรี

คลาส Node เก็บของตามสไลด์ คือ index ตำแหน่ง x y โหนดแม่ ระยะจากแม่ ระยะจากจุดเริ่ม และจุดต่างๆ ตามเส้นที่ลากจากแม่มาหาโหนดนี้

ไล่ฟังก์ชันตามลำดับการทำงานของหนึ่งรอบ:

**populate_node** สุ่มจุดใหม่ ส่วนใหญ่เป็นช่องว่างสุ่มๆ แต่ประมาณสิบเปอร์เซ็นต์ของรอบจะเลือกตำแหน่งเป้าหมายเลย เพื่อให้ต้นไม้โตเอียงไปทางเป้าหมายบ้าง

**find_node_nearest** หาโหนดในต้นไม้ที่ใกล้จุดสุ่มที่สุด

**steer** ลากเส้นจากโหนดนั้นไปทางจุดสุ่ม แต่ยาวไม่เกินระยะก้าวสูงสุด `expand_dis` ซึ่งตั้งไว้หนึ่งเมตร ระหว่างทางวางจุดย่อยทุกสิบเซนติเมตรเก็บไว้ตรวจชน และคำนวณระยะจากจุดเริ่มของโหนดใหม่ไว้ด้วย

**check_obstacle** เอาจุดย่อยทั้งหมดบนเส้นนั้นไปดูในกริด ถ้ามีจุดไหนตกบนช่องที่ไปไม่ได้ ก็ทิ้งโหนดนี้

**find_node_within_radius** หาโหนดที่อยู่ในรัศมีรอบโหนดใหม่ รัศมีนี้ค่อยๆ เล็กลงตามจำนวนโหนดที่เพิ่มขึ้น ใช้สูตรเดียวกับงานก่อนหน้า จำกัดสูงสุดห้าเท่าของระยะก้าว

**choose_parent** นี่คือจุดที่ทำให้ RRT* ต่างจาก RRT ธรรมดา แทนที่จะต่อโหนดใหม่เข้ากับโหนดใกล้สุดทันที มันดูโหนดข้างเคียงทั้งหมดว่าต่อกับตัวไหนแล้วระยะจากจุดเริ่มถึงโหนดใหม่สั้นที่สุด โดยเส้นไม่ชน ผมเรียงตามระยะแล้วตรวจชนทีละตัว ตัวแรกที่เส้นไม่ชนคือตัวที่ถูกที่สุดพอดี เลยไม่ต้องตรวจครบทุกตัว

**rewire** หลังจากต่อโหนดใหม่แล้ว ย้อนไปดูโหนดข้างเคียงว่า ถ้าเปลี่ยนมาต่อผ่านโหนดใหม่แล้วระยะจากจุดเริ่มสั้นลง และเส้นไม่ชน ก็ตัดแม่เดิมแล้วเปลี่ยนมาต่อกับโหนดใหม่ นี่คือที่ทำให้เส้นทางค่อยๆ ตรงขึ้นเรื่อยๆ เมื่อรันรอบมากขึ้น

**propagate_cost_to_leaves** เมื่อโหนดหนึ่งถูกเปลี่ยนแม่ ระยะจากจุดเริ่มของลูกหลานทั้งหมดต้องอัปเดตตาม ฟังก์ชันนี้เดินไล่ลงไปทุกลูกทุกหลาน ผมเก็บรายชื่อลูกของแต่ละโหนดไว้ เลยไล่ได้ทันที ไม่ต้องวนหาทั้งต้นไม้

**search_best_goal_node** พอวนครบจำนวนรอบ ก็หาโหนดที่อยู่ใกล้เป้าหมายไม่เกินระยะก้าว และลากเส้นไปหาเป้าหมายได้โดยไม่ชน เลือกอันที่ระยะรวมสั้นที่สุด

**generate_final_course** ไล่ย้อนจากเป้าหมายกลับไปหาจุดเริ่มตามโหนดแม่ แล้วกลับลำดับให้เป็นจากจุดเริ่มไปเป้าหมาย ซึ่งก็คือลำดับที่หุ่นต้องวิ่งตาม

**planning** คือลูปหลัก วนตามจำนวนรอบที่ตั้งไว้ ห้าพันรอบ ถ้าครบแล้วยังไม่เจอทางไปเป้าหมาย จะวนต่ออีกรอบละสองพันจนเจอ หรือถึงเพดานสามหมื่นรอบ ผลคือรายการพิกัดโหนดเรียงตามลำดับ

### 2.6 ตรวจเทียบฉากจริง และผลลัพธ์

*(เลื่อนไปที่ world_clearance และ main)*

สุดท้ายเซฟออกมาสามอย่าง `plan.json` ไว้ให้ตัวขับใช้ `path_nodes.csv` เป็นตารางพิกัดโหนด และ `plan.png` เป็นรูปที่โชว์ตอนต้น

## 3. ตัวสั่งให้หุ่นเกิดที่จุดเริ่ม — rrt_nav.launch.py

*(หน้าจอ: สลับไปที่ไฟล์ rrt_nav.launch.py)*

ข้อที่โจทย์ให้หุ่นอยู่ที่ตำแหน่งเริ่มต้นแบบสุ่ม ใน Gazebo ทำโดยให้หุ่นเกิดที่ตำแหน่งนั้นเลย ไม่ได้เกิดที่เดิมแล้วย้ายทีหลัง

ไฟล์ launch นี้อ่าน `plan.json` เอาตำแหน่งเริ่มต้น x y และ theta ไปส่งให้ไฟล์ launch หลักของซิม ซึ่งผมเพิ่มตัวเลือก `spawn_x` `spawn_y` `spawn_yaw` ไว้ให้ปรับตำแหน่งที่หุ่นเกิดได้ ถ้าไม่ใส่ก็เกิดที่ประตูทางเข้าเหมือนเดิม

จากนั้นรอยี่สิบวินาทีให้ Gazebo โหลดฉากกับหุ่นเสร็จ แล้วค่อยเริ่มโปรแกรมตัวขับ และตั้งไว้ว่าพอโปรแกรมตัวขับจบ ให้ปิด Gazebo ทั้งหมดด้วย

## 4. โปรแกรมตัวขับ — follow_path_gazebo_660610829.py

*(หน้าจอ: สลับไปที่ไฟล์ follow_path_gazebo)*

### 4.1 เทียบกับตัวอย่างใน CoppeliaSim

โจทย์เดิมให้ใช้ zmqRemoteApi กับคำสั่ง `sim.setJointTargetVelocity` ซึ่งเป็นของ CoppeliaSim ใน Gazebo ไม่มีของพวกนี้ ผมทำให้เทียบกันได้แบบนี้ ตำแหน่งหุ่นจริงอ่านจาก topic `/odom` แทน `getObjectPosition` และแทนที่จะตั้งความเร็ว joint ของมอเตอร์ตรงๆ โปรแกรมคำนวณความเร็วล้อซ้ายและล้อขวาเป็นเรเดียนต่อวินาทีเหมือนกัน แล้วส่งเข้าไปที่ topic `/cmd_vel` ปลั๊กอิน diff drive ของ Gazebo จะรับไปแล้วตั้งความเร็วให้ joint ของล้อทั้งสี่ให้เอง ซึ่งคือสิ่งเดียวกับที่ `setJointTargetVelocity` ทำ

### 4.2 ค่าคงที่ต้นไฟล์

รัศมีล้อศูนย์จุดหนึ่งห้าเมตร และระยะห่างล้อซ้ายขวาหนึ่งจุดศูนย์แปดเมตร สองตัวนี้ดึงมาจากไฟล์โมเดลหุ่น ใช้แปลงความเร็วตัวหุ่นเป็นความเร็วล้อ ตามด้วยค่าที่ใช้ปรับการควบคุม เช่น ระยะที่ถือว่าถึงเป้าหมายสิบเซนติเมตร มุมที่ถือว่าหันถูกแล้วสามองศา ความเร็วเลี้ยวสูงสุด

### 4.3 ฟังก์ชัน interpolate_path

*(เลื่อนไปที่ interpolate_path)*

ตรงนี้คือข้อ interpolate ระหว่างโหนด โหนดจาก RRT* ห่างกันประมาณหนึ่งเมตร ถ้าสั่งหุ่นวิ่งไปทีละโหนดตรงๆ จะกระตุก ฟังก์ชันนี้แบ่งแต่ละช่วงระหว่างโหนดเป็นเส้นตรงที่มีจุดคั่นทุกสิบเซนติเมตร ได้เป็นเส้นทางละเอียดที่ตัวควบคุมใช้อ้างอิง

### 4.4 ฟังก์ชัน wheel_speeds และ body_speed

*(เลื่อนไปที่สองฟังก์ชันนี้)*

`wheel_speeds` รับความเร็วเดินหน้าและความเร็วหมุนของตัวหุ่น แล้วคำนวณว่าล้อซ้ายกับล้อขวาต้องหมุนกี่เรเดียนต่อวินาที ถ้าจะเลี้ยวซ้าย ล้อขวาต้องเร็วกว่าล้อซ้าย ถ้าความเร็วล้อเกินเพดานหกเรเดียนต่อวินาที จะลดทั้งสองข้างลงด้วยสัดส่วนเดียวกัน เพื่อให้ยังเลี้ยวเท่าเดิม แค่ช้าลง

`body_speed` ทำกลับกัน แปลงความเร็วล้อกลับเป็นความเร็วตัวหุ่น ใช้ตอนส่งเข้า `/cmd_vel`

### 4.5 คลาส PathFollower

*(เลื่อนไปที่ class PathFollower)*

**ตอนเริ่มต้น** โหลดเส้นทาง interpolate แล้วคำนวณความยาวสะสมตามเส้นไว้ ใช้หาจุดที่อยู่ข้างหน้าในระยะที่ต้องการได้ง่าย ติดตามตำแหน่งหุ่นจาก `/odom` และข้อมูลเลเซอร์จาก `/scan`

**front_blocked** ตัวป้องกันไว้ก่อน ถ้ามีอะไรเข้ามาอยู่ในกรอบหน้าหุ่น ห่างจากหน้าตัวหุ่นไม่ถึงยี่สิบเซนติเมตร หุ่นจะหยุดรอ และถ้าติดอยู่เกินสิบวินาทีจะยกเลิก ปกติเส้นทางที่วางแผนไว้ไม่ผ่านใกล้ของอยู่แล้ว มันเลยไม่ค่อยทำงาน

**turn_ahead** ดูว่าเส้นทางข้างหน้าในระยะหนึ่งเมตรครึ่งหักมุมมากแค่ไหน ใช้ชะลอความเร็วก่อนถึงโค้ง

**control** คือหัวใจ ทำงานทุกห้าสิบมิลลิวินาที มีสองโหมด

โหมดแรกคือ TRACK วิ่งตามเส้นทาง ขั้นตอนคือ หาจุดบนเส้นทางที่ใกล้ตัวหุ่นที่สุด แล้วเดินไปข้างหน้าตามเส้นทางศูนย์จุดหกเมตร เป็นจุด look-ahead จากนั้นคำนวณว่าหุ่นหันไม่ตรงทิศไปหาจุดนั้นกี่เรเดียน เรียกว่ามุมคลาด

ถ้ามุมคลาดมากเกินประมาณสี่สิบหกองศา หุ่นจะหยุดเดินหน้าแล้วหมุนอยู่กับที่จนมุมเหลือน้อยกว่าสิบสี่องศาค่อยเดินต่อ ใช้เงื่อนไขสองค่าต่างกัน เพื่อไม่ให้สลับไปมาถี่ๆ

ถ้ามุมคลาดน้อย ความเร็วเดินหน้าตั้งจากความเร็วสูงสุด ลดลงเมื่อมุมคลาดมาก ลดลงอีกเมื่อข้างหน้ามีโค้ง และลดลงเมื่อใกล้เป้าหมาย ส่วนความเร็วเลี้ยวเป็นสัดส่วนกับมุมคลาด นี่คือการ steer แบบง่ายๆ ที่เรียกว่า pure pursuit คือเล็งไปที่จุดข้างหน้าตลอด

เสร็จแล้วส่งความเร็วนั้นผ่าน `send` ซึ่งแปลงเป็นความเร็วล้อ ตามที่อธิบายไว้

โหมดที่สองคือ FINAL_ROTATE เมื่อตำแหน่งหุ่นห่างเป้าหมายไม่ถึงสิบเซนติเมตร หุ่นหยุดเดินหน้า แล้วหมุนอยู่กับที่ให้หันตรงตามมุม theta ของเป้าหมาย พอมุมคลาดไม่เกินสามองศาต่อเนื่องหกรอบ ถือว่าจบ

**finish** ตอนจบ สั่งหยุดล้อ คำนวณและพิมพ์ผล ตำแหน่งคลาดจากเป้าหมายเท่าไหร่ หันคลาดกี่องศา และตลอดทางหุ่นเบี่ยงจากเส้นแผนที่สุดเท่าไหร่ แล้วเซฟเส้นทางที่วิ่งจริงลง `trajectory.csv`

อ่านไฟล์ `plan.json` เริ่ม ROS แล้วหมุนตัวควบคุมไปเรื่อยๆ จนกว่าจะเสร็จ ถ้ารันเกินสิบห้านาทีจะยกเลิกเอง

## 5. ผลการรัน

*(หน้าจอ: รัน `ros2 launch diffbot_sim rrt_nav.launch.py` ให้เห็น Gazebo แล้วสลับไปโชว์ `result.png`)*

ในรูปผลลัพธ์ เส้นน้ำเงินคือเส้นทางที่แผนไว้ เส้นแดงคือที่หุ่นวิ่งจริงใน Gazebo ซ้อนกันเกือบสนิท ฝั่งขวาคือคำสั่งความเร็วล้อซ้ายขวาตลอดการวิ่ง จะเห็นว่าตอนต้นล้อสองข้างหมุนสวนทางกัน คือหุ่นหมุนอยู่กับที่หันหาโหนดแรก จากนั้นหมุนไปทางเดียวกันตอนเดินหน้า และเริ่มต่างกันตอนเลี้ยว ตอนท้ายสวนทางกันอีกครั้งตอนหมุนให้ตรงทิศเป้าหมาย

ผมสุ่มรันสี่ชุด จุดเริ่มกับเป้าหมายคนละคู่ ทุกชุดหุ่นถึงเป้าหมายโดยไม่ชน คลาดจากเป้าหมายไม่เกินสิบเซนติเมตร หันคลาดไม่เกินสามองศา และเบี่ยงจากเส้นแผนสูงสุดประมาณยี่สิบเซนติเมตร

## 6. ข้อจำกัดที่ควรบอกไว้

- วางแผนเฉพาะตำแหน่ง ส่วนมุม theta จัดการตอนเกิดและตอนปลายทาง ระหว่างทางไม่ได้คำนึงถึง
- ถ้าแผนที่ OGM สำรวจไม่ครบ ช่องที่ไม่เคยเห็นจะถูกห้ามเดิน อาจทำให้บางทางผ่านไม่ได้ทั้งที่จริงเดินได้
- RRT* สุ่ม รันแต่ละครั้งเส้นทางไม่เหมือนกัน แต่ถ้าใช้ seed เดียวกันจะได้เส้นเดิม
- ของที่เลเซอร์มองไม่เห็น ต้องอาศัยข้อมูลจากไฟล์ฉากมาเติม ถ้าเป็นหุ่นยนต์จริงที่ไม่มีไฟล์ฉาก ต้องใช้เซนเซอร์เพิ่มหรือเลเซอร์ที่ติดต่ำลง
